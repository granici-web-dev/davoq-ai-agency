# AssistWidget

White-label чат-ассистент для сайтов. Один `<script>` ставит на сайт виджет,
который отвечает посетителям по материалам компании, при незнании собирает
контакты и передаёт заявку отделу продаж.

Продукт сдаётся в аренду многим клиентам сразу. Чтобы это не превращалось
в копипасту кода под каждого, система разложена на три слоя.

---

## Три слоя

```
┌─ ДВИЖОК ──────────────────────────────────────────────────────────┐
│  src/engine/                                                      │
│  Одинаков для всех клиентов и всех ниш.                           │
│  Диалог, RAG, виджет, панель, коннекторы, очереди, метрики,       │
│  уведомления, изоляция клиентов.                                  │
│  Меняется релизом.                                                │
└───────────────────────────────────────────────────────────────────┘
            ▲ читает
┌─ ВЕРТИКАЛЬ ───────────────────────────────────────────────────────┐
│  src/verticals/<ниша>/                                            │
│  Одинакова для всех клиентов ниши.                                │
│  Правила разговора о цене, типовые возражения, цель разговора,    │
│  сценарий квалификации, пороги поиска, чек-лист материалов.       │
│  Файлы в репозитории, версионируются вместе с кодом.              │
└───────────────────────────────────────────────────────────────────┘
            ▲ наследует и переопределяет
┌─ КЛИЕНТ ──────────────────────────────────────────────────────────┐
│  clients/<клиент>/config.yaml  ──apply──▶  база данных            │
│  Бренд, домены, язык, каталог, цены, шоурумы, тон, брендинг,      │
│  адрес для заявок, тариф.                                         │
│  Файл — вход онбординга. Правда в рантайме — база.                │
└───────────────────────────────────────────────────────────────────┘
```

### Почему конфиг клиента не читается в рантайме

Приветствие, тему виджета, адрес для заявок и утверждённые ответы клиент правит
сам из панели. Если бы правдой был файл в репозитории, то либо панель перестала бы
работать, либо файл и база расходились бы — молча.

Поэтому `config.yaml` — **вход команды `apply`**, а не источник рантайма:

```
clients/sofabelle/config.yaml ──apply──▶ база ──читает──▶ движок
```

`apply` идемпотентна, показывает diff до записи и **не затирает то, что клиент
поменял сам**. Она помнит, что записала в прошлый раз (`tenants.applied_config`),
и расхождение с этим снимком означает правку клиента. Перезаписать всё равно можно
флагом `--force`, но это осознанное действие, а не побочный эффект релиза.

### Что вертикаль переопределить не может

`Nature`, `Data versus commands`, `Scope`, `Priority` — блоки системного промпта,
которые задаёт движок. Первый — требование AI Act Art. 50 (бот, назвавшийся
человеком, попадает под ст. 5 со штрафом до 7% оборота), второй — защита от
инъекций через материалы клиента. Попытка задать их в шаблоне ниши роняет
загрузку с внятной ошибкой; это проверяется, а не остаётся договорённостью.

## Быстрый старт

```bash
docker compose up -d          # postgres + redis + локальный почтовый ящик
npm install
npm run migrate               # под DATABASE_ADMIN_URL, правами владельца
npm run build:widget && npm run build:admin
npm run dev                   # API на :3779
npm run worker                # индексация, сверка диска, уведомления
```

Проверить, что всё живо:

```bash
npm run smoke                 # диалог: приветствие → квалификация → заявка
npm run test:isolation        # клиент А не достаёт документы клиента Б
```

Письма локально ловит Mailpit: **http://localhost:8025**, наружу ничего не уходит.

## Как добавить нового клиента

```bash
npm run client new acme -- --name "Acme Mobilă" --domain acme.ro \
                           --vertical furniture --locale ro
```

Команда создаёт `clients/acme/` — конфиг из шаблона ниши, пустую структуру базы
знаний по разделам, README — и печатает **чек-лист материалов**, которые надо
запросить у клиента. Чек-лист берётся из вертикали, а не выдумывается каждый раз:
самая дорогая ошибка при заведении — узнать на третьей неделе пилота, что тканей
и сроков доставки нам никто не присылал.

Дальше:

1. Заполнить `clients/acme/config.yaml` — всё, где стоит `TODO`.
2. Положить логотип в `clients/acme/assets/` и указать путь в конфиге.
3. Сложить материалы в `clients/acme/knowledge/`.
4. Применить:

```bash
npm run client apply acme -- --dry-run   # сначала посмотреть, что изменится
npm run client apply acme
```

5. Завести пользователя панели и отдать клиенту сниппет из раздела «Установка»:

```bash
npm run cli create-user <tenantId> director@acme.ro '<пароль>'
```

Полезное:

```bash
npm run client list       # кто заведён
npm run client metrics    # показы, разговоры, контакты, заявки по каждому
```

### Что задаётся конфигом, а что клиент правит сам

| Задаёт онбординг | Правит клиент из панели |
|---|---|
| Домены, язык, тариф, ниша | Приветствие и тексты виджета |
| Отправитель писем (`from`) | Адрес получателя заявок |
| Брендинг, логотип | Тема и цвета |
| Правила о ценах, квалификация | Материалы, утверждённые ответы |
| Набор экранов панели | — |

Отправитель писем в панель намеренно не выведен: адрес завязан на SPF/DKIM домена,
и свободный ввод здесь тихо отправляет всю почту клиента в спам.

## Как добавить новую вертикаль

```
src/verticals/<ниша>/
  vertical.yaml          # манифест
  prompt/
    price.md             # правила разговора о цене
    qualification.md     # как собирать бриф и когда передавать заявку
    goal.md              # к чему ведём разговор
    objections.md        # типовые возражения ниши
```

`vertical.yaml` описывает: поля квалификации, пороги поиска, чек-лист материалов
и какие файлы промпта подключать. Схема проверяется при загрузке — неизвестное
поле или пункт чек-листа не строкой роняют старт с объяснением, а не превращаются
в `[object Object]` на экране (проверено на себе).

### Плейсхолдеры в шаблонах промпта

Значения подставляются из конфига клиента на рантайме:

| Плейсхолдер | Откуда |
|---|---|
| `{brand_name}` | `name` клиента |
| `{bot_name}` | имя бота из настроек виджета |
| `{locale}` | язык по умолчанию |
| `{showrooms}` | `showrooms` из конфига |
| `{tone}` | `brand.tone` |
| `{catalog_context}` | найденные фрагменты базы знаний |
| любое поле `profile` | по своему имени |

Неизвестный плейсхолдер — **ошибка загрузки**, а не пустое место: промпт с дырой
посередине обнаружился бы по странным ответам бота у живого клиента.

Тон пишется **по-английски**: системный промпт английский целиком, и чужой язык
в нём протекает в ответ посетителю. На каком языке отвечает бот, задаёт `locale`.

Проверить собранный промпт:

```bash
npx tsx scripts/dump-prompt.mts <tenantId>
```

## Изоляция клиентов

Утверждение: **запрос одного клиента физически не может достать документы
другого.** Не «мы стараемся фильтровать» — база сама не отдаёт чужие строки.

Как это устроено:

- 14 таблиц под `ROW LEVEL SECURITY` с `FORCE` — политики действуют даже
  на владельца таблицы.
- Приложение подключается ролью `assistwidget_app` (`NOSUPERUSER`, `NOBYPASSRLS`).
  Это ключевая деталь: владелец базы обходит даже `FORCE RLS`, и под ним изоляция
  существует только на бумаге.
- Контекст ставится через `set_config(..., is_local => true)` внутри транзакции —
  соединение из пула не может унести чужой `tenant_id` следующему запросу.
- Поиск фильтрует по `tenant_id` **дополнительно** к RLS.
- Файлы клиента лежат под префиксом его тенанта.

Два соединения с разными правами:

| Переменная | Роль | Для чего |
|---|---|---|
| `DATABASE_URL` | `assistwidget_app` | всё приложение |
| `DATABASE_ADMIN_URL` | владелец | только миграции и заведение тенанта |

`DATABASE_ADMIN_URL` **не должен попадать в конфигурацию веб-процесса.**

Проверяется тестом, который пытается смошенничать: ходит под одним тенантом
и просит данные другого, явно подставляя чужой `tenant_id`.

```bash
npm run test:isolation
```

## Секреты

В коде и в конфигах клиентов их нет. Токены Google Drive и ключи коннекторов
шифруются `SECRETS_KEY` и лежат в базе; клиент подключает их сам из панели.

**`SECRETS_KEY` менять нельзя** — со сменой ключа всё зашифрованное станет
нечитаемым. Переменные окружения перечислены в `.env.example`.

## Структура

```
src/
  engine/          движок: api, rag, ingest, llm, drive, notify, widget, admin, prompt
  verticals/       шаблоны ниш
  platform/        онбординг и CLI
clients/           конфигурации клиентов (вход онбординга)
migrations/        схема базы
scripts/           smoke, проверка изоляции, печать промпта
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | API-сервер |
| `npm run worker` | индексация, сверка Drive, автопроверка пробелов, письма |
| `npm run migrate` | миграции |
| `npm run smoke` | живой диалог до переданной заявки |
| `npm run test:isolation` | проверка изоляции клиентов |
